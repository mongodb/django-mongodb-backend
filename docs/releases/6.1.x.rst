============================
Django MongoDB Backend 6.1.x
============================

6.1.1
=====

*Unreleased*

Bug fixes
---------

- Index definitions using ordering expressions (e.g.
  ``Index(F("priority").desc(), name="...")``) are now created instead of
  being silently skipped. Expressions that can't be translated into MongoDB
  index keys (anything other than :class:`~django.db.models.F` and
  :class:`~django.db.models.OrderBy` field orderings) are skipped without
  raising an error.
- Fixed a ``migrate`` crash when an ``Index`` subclass reports
  ``contains_expressions=False`` for an index with expressions.
- Indexes that earlier versions skipped aren't retroactively created by
  already-applied ``AddIndex`` migrations: create a new migration or add the
  index manually on upgraded deployments.

6.1.0
=====

*August 17, 2026*

Initial release from the state of :ref:`django-mongodb-backend 6.0.4
<django-mongodb-backend-6.0.4>`.

Backwards incompatible changes
------------------------------

- Django 6.1 is now required. Django 6.0 is supported by the
  ``django-mongodb-backend`` 6.0.x series.
- Defining indexes and constraints on embedded models using ``unique=True``,
  ``db_index=True``, ``Meta.constraints``, ``Meta.indexes``, and
  ``Meta.unique_together`` is no longer supported, as per the
  :ref:`deprecation timeline <inline-constraints-and-indexes-deprecation>`.
  Use :class:`~django_mongodb_backend.indexes.EmbeddedFieldIndex` and
  :class:`~django_mongodb_backend.constraints.EmbeddedFieldUniqueConstraint`
  on the top-level model instead.
